> [!summary]
> 일정이 넉넉하지 않아 고객에게 직접 보이는 화면만 hi-fi 디자인으로 진행하고, 나머지 3개 웹·앱은 와이어프레임 기반으로 구현한 뒤 디자인 검수를 진행한다. 카카오·Apple 로그인은 앱에서 네이티브 인증 앱을 호출하는 방향을 목표로 하되, 구체적인 구현 방식은 리서치 후 정하기로 했다.

## 회의

### 논의 내용

- 전체 일정을 고려해 모든 웹·앱을 hi-fi 디자인까지 완성한 뒤 개발하는 방식은 적용하지 않는다.
- 고객에게 직접 노출되는 화면은 사용자 경험과 브랜드 인상을 위해 hi-fi 디자인을 완성한다.
- 그 외 3개 웹·앱은 와이어프레임을 기준으로 프론트엔드가 세부 UI를 판단해 구현한다.
- 이미 마련된 공통 컴포넌트를 활용해 구현 속도를 확보하고, 구현 결과를 디자인 담당자가 검수한다.

### 결정

- 고객 노출 화면: hi-fi 디자인 후 구현.
- 나머지 3개 웹·앱: 와이어프레임 기반 프론트엔드 구현 후 디자인 검수.
- 와이어프레임에 정의되지 않은 세부 UI는 기존 공통 컴포넌트와 제품 맥락을 기준으로 프론트엔드가 결정한다.

### 후속 작업

- hi-fi 디자인이 필요한 화면의 범위를 확정한다.
- 나머지 3개 웹·앱의 와이어프레임과 공통 컴포넌트를 기준으로 구현을 진행한다.
- 구현 후 디자인 검수 일정과 수정 반영 방식을 정한다.

### 미결 사항

- hi-fi 대상 화면과 와이어프레임 구현 대상 화면의 세부 목록
- 프론트엔드가 자율 결정할 수 있는 범위와 디자인 확인이 필요한 기준
- 디자인 검수 시점, 담당자, 수정 반영 우선순위

### 앱 소셜 로그인

- 고객 플랫폼의 앱 환경에서 카카오 로그인 버튼을 누르면 웹 브라우저가 아니라 카카오톡 앱을 호출하는 네이티브 로그인 흐름을 목표로 한다.
- Apple 로그인도 앱 환경에 맞는 네이티브 인증 흐름을 우선 검토한다.
- 네이티브 로그인은 웹 로그인보다 Expo·React Native에서 플랫폼별 설정, 앱 전환·callback, SDK 또는 wrapper 관리 등 프론트엔드 관리 포인트가 늘어날 수 있다.

### 앱 소셜 로그인 결정

- 카카오·Apple 로그인은 앱 호출형 네이티브 인증을 목표로 한다.
- 사용할 SDK, wrapper, Expo 설정과 세부 callback 구조는 확정하지 않는다.
- 각자 구현 가능성을 리서치한 뒤 방식을 비교한다.

### 앱 소셜 로그인 후속 작업

- Kakao native SDK와 React Native wrapper의 Android·iOS 지원 범위를 비교한다.
- Expo AppleAuthentication과 Apple 로그인 플랫폼별 제약을 확인한다.
- 앱 전환·복귀, 딥링크 또는 URL scheme, 로그인 취소·실패, 백엔드 토큰 교환 흐름을 확인한다.
- 고객사에 iOS Bundle ID, Apple Team ID, Android Package ID, Android 서명 fingerprint를 요청한다.

### 앱 소셜 로그인 미결 사항

- 카카오·Apple 로그인에 사용할 최종 라이브러리와 Expo 적용 방식
- Android·iOS별 앱 등록값, URL scheme, callback 설정
- 로그인 토큰 검증과 기존 휴대폰 회원 연결을 담당할 백엔드 흐름
- 고객사 미제공 값: iOS Bundle ID, Apple Team ID, Android Package ID, Android 서명 fingerprint
