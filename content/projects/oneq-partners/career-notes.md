> 이 노트는 이력서 문장을 과장 없이 만들기 위한 근거 저장소다. 현재 확인된 내용과 앞으로 채워야 할 내용을 분리하며, 실제 완료 범위와 수치가 확인될 때마다 갱신한다.

## 프로젝트 한 줄 설명

공인중개사 등 영업 파트너의 QR로 유입된 고객 요청을 운영사가 상담하고 여러 공급업체의 방문·온라인 견적과 연결해 비교와 최종 선택까지 지원하는 다자간 견적 중개 플랫폼 프로젝트.

## 프로젝트 규모와 서비스 구성

- 영업 파트너 모바일 웹
- 고객용 WebView 하이브리드 앱
- 운영사용 PC 백오피스
- 공급업체 모바일 웹

파트너 신청과 QR 발급부터 고객 상담, 공급업체 주선, 견적 비교와 최종 견적 합의까지 이어지는 여러 사용자 간 업무 흐름을 다룬다. 고객–공급업체 계약과 계약 이후 실제 서비스 수행은 1차 범위에서 제외한다.

## 현재 확인된 담당 범위

- 영업 파트너 모집·신청용 공개 랜딩을 위한 Astro 기술 셸과 프로젝트 경계 구성
- Astro 기반 정적 페이지 구조와 프런트엔드 경계 설정
- 필요한 상호작용만 React island로 분리하는 기준 수립
- 반응형 웹, SEO, 공유 미리보기를 고려한 기반 구성
- 미확정 폼·API·개인정보 정책을 코드와 분리해 관리

## 경험을 설명할 때 강조할 맥락

- 단일 화면이 아니라 영업 파트너 모집과 신청 전환을 담당하는 공개 채널의 프런트엔드 기반을 설계했다.
- 네 종류의 사용자 채널 중 랜딩이 담당해야 할 범위와 별도 파트너 포털이 담당할 범위를 구분했다.
- 오프라인 제휴와 상담이 포함된 업무를 고려해, 화면에서 확정적으로 약속할 수 있는 정보와 미확정 정책을 분리했다.
- 프로젝트 전체 요구사항을 그대로 구현하는 대신 현재 저장소가 소유하는 랜딩 영역에 필요한 정보 구조와 기술 경계를 정의했다.

## 기술 키워드

- Astro 7
- React 19
- TypeScript
- pnpm
- Static Site Generation
- Islands Architecture
- Responsive Web
- SEO metadata

## 이력서 문장 초안

현재 진행 중인 범위를 표현할 때 사용할 수 있는 초안이다.

- 다자간 견적 중개 플랫폼의 영업 파트너 모집 랜딩을 Astro 기반 static-first 구조로 설계·구현 중이다.
- 정적 콘텐츠는 Astro 컴포넌트로 유지하고 상태가 필요한 기능만 React island로 분리하는 아키텍처 기준을 수립했다.
- 미확정 신청 정책과 API를 구현에서 분리해 요구사항 변경에 대응할 수 있는 프로젝트 경계를 정리했다.
- 영업 파트너, 고객, 운영사, 공급업체로 구성된 다중 사용자 서비스에서 공개 랜딩과 인증 후 포털의 책임을 분리했다.

완료되지 않은 기능이나 검증되지 않은 효과를 완료 성과처럼 사용하지 않는다.

## 프로젝트 종료 전 채울 항목

- 프로젝트 기간
- 팀 구성과 나의 역할
- 직접 소유한 화면·기능·기술 결정
- 가장 어려웠던 제약과 선택한 해결책
- 성능, 접근성, 전환율, 개발 속도 등 측정 가능한 결과
- 배포 환경과 운영 경험
- 코드, 테스트, 문서, 화면 등 성과를 증명할 근거
- 협업 과정에서 조율하거나 개선한 내용
