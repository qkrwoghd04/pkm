> 원큐파트너스는 영업 파트너의 QR을 통해 유입된 고객 요청을 운영사가 상담하고 여러 공급업체의 견적과 연결하는 다자간 견적 중개 플랫폼이다. 파트너 모집부터 고객 상담, 견적 비교, 공급업체 선택과 최종 견적 합의까지 이어지는 업무 흐름을 여러 사용자 채널로 지원한다.

## 프로젝트 개요

원큐파트너스는 공인중개사와 부동산 중개업소 같은 영업 파트너가 고객을 소개하고, 운영사가 고객의 요구사항을 구체화해 적합한 공급업체의 견적을 중개하는 신규 SI 프로젝트다.

고객은 하나의 서비스 제공업체에 바로 연결되는 대신 여러 공급업체의 조건을 비교할 수 있고, 영업 파트너는 고유 QR을 통해 자신이 유입한 고객의 진행 상황을 허용된 범위에서 확인할 수 있다. 운영사는 상담, 공급업체 주선, 견적 요청, 방문 일정 조율과 최종 진행 확인을 담당한다.

## 해결하려는 문제

- 고객이 서비스별 공급업체를 직접 탐색하고 각각 상담해야 하는 비용을 줄인다.
- 고객의 초기 요청을 실제 견적에 필요한 요구사항으로 구체화한다.
- 여러 공급업체의 방문·온라인 견적을 한 흐름에서 비교할 수 있게 한다.
- 영업 파트너가 고객을 소개한 출처와 이후 진행 상태를 추적할 수 있게 한다.
- 운영사가 상담, 견적 요청, 일정과 공급업체 응답을 일관된 상태로 관리하게 한다.

## 참여자와 역할

원큐파트너스는 다음 네 참여자를 하나의 견적 흐름으로 연결한다.

- **영업 파트너:** 파트너 신청과 제휴 절차를 거쳐 고유 QR을 발급받고 고객을 유입한다.
- **고객:** 서비스 카테고리를 선택해 상담을 신청하고, 공급업체별 견적을 비교해 최종 공급업체와 견적을 선택한다.
- **1Q 운영사:** 고객 상담과 요구사항 수집, 공급업체 주선, 견적 요청, 방문 일정 조율과 최종 진행 가능 여부 확인을 담당한다.
- **공급업체:** 요청받은 조건을 검토하고 방문 또는 온라인 견적을 제공하며, 고객 선택 후 해당 조건으로 진행 가능한지 최종 확인한다.

## 핵심 업무 흐름

1. 영업 파트너가 신청하고 외부 제휴 절차를 완료한다.
2. 운영사가 신청을 승인하고 파트너 계정과 고유 QR을 발급한다.
3. 고객이 파트너 QR을 통해 접속하고 서비스 상담을 신청한다.
4. 운영사가 고객에게 연락해 필요한 서비스와 세부 조건을 정리한다.
5. 운영사가 적합한 공급업체를 선정해 견적 또는 방문 상담을 요청한다.
6. 공급업체가 온라인 견적을 제출하거나 현장 방문 후 최종 견적을 제공한다.
7. 고객이 여러 견적을 비교하고 원하는 공급업체와 견적을 선택한다.
8. 운영사가 선택된 공급업체의 최종 진행 가능 여부를 확인한다.
9. 진행할 수 있으면 공급업체와 견적 합의가 완료되고, 불가능하면 다른 유효 견적을 선택하거나 공급업체 주선 단계로 돌아간다.

이 프로젝트의 1차 업무 종료점은 **고객과 선택 공급업체가 최종 공급업체와 견적에 합의한 시점**이다. 실제 계약 체결과 계약 이후 서비스 이행은 별도 영역으로 본다.

## 서비스 구성

| 서비스                | 주요 사용자                        | 역할                                                                   |
| --------------------- | ---------------------------------- | ---------------------------------------------------------------------- |
| 영업 파트너 모바일 웹 | 공인중개사·중개업소 등 영업 파트너 | 파트너 모집·신청, 고유 QR 발급, 허용된 고객 유입 진행 정보 확인        |
| 고객 하이브리드 앱    | 서비스 이용 고객                   | 업종 선택, 상담 신청, 비교견적 확인, 공급업체와 견적 선택              |
| 운영사 백오피스       | 상담사·운영 담당자                 | 상담 접수, 요구사항 수집, 공급업체 주선, 견적·일정·최종 진행 상태 관리 |
| 공급업체 모바일 웹    | 서비스 공급업체                    | 견적 요청 확인, 방문·온라인 견적 대응, 최종 진행 가능 여부 확인        |

고객 채널은 iOS·Android를 대상으로 하는 WebView 기반 하이브리드 앱이며, 나머지 채널은 각 사용 환경에 맞춘 웹으로 구성된다.

## 1차 범위

### 포함

- 영업 파트너 모집 랜딩과 신청 진입점
- 파트너별 QR을 통한 고객 유입과 출처 식별
- 고객의 서비스 선택과 상담 신청
- 운영사의 요구사항 수집과 공급업체 주선
- 방문 견적과 온라인 견적 흐름
- 공급업체별 비교견적과 고객의 최종 선택
- 선택 공급업체의 진행 가능 여부 확인
- 최종 공급업체와 견적 합의 완료

### 제외

- 고객과 공급업체 사이의 계약 체결과 계약 확정
- 계약서 업로드, 수신, 열람, 승인과 보관
- 계약 이후 실제 공사, 설치, 제작, 배송과 서비스 수행 관리

## 프로젝트의 기술·설계 특징

- 네 종류의 사용자가 서로 다른 권한과 화면을 사용하는 다중 채널 구조
- 모바일 웹, 하이브리드 앱, PC 백오피스를 함께 제공하는 멀티 프런트엔드 구성
- 온라인 견적과 현장 방문 견적이 함께 존재하는 온·오프라인 결합 업무 흐름
- 공급업체 진행 불가, 대체 견적 부재 같은 되돌림 조건을 포함한 상태 기반 프로세스
- 파트너별 QR을 고객 유입 출처와 진행 정보에 연결하는 추적 구조
- 계약 도메인과 견적 중개 도메인의 책임을 명시적으로 분리한 MVP 경계

상세 정책과 화면별 요구사항은 계속 변경될 수 있으므로 현재 구현, 테스트와 각 프로젝트 저장소의 최신 문서를 우선한다.

## 내가 다룬 영역

- 공인중개사·부동산 중개업소를 대상으로 한 영업 파트너 모집·신청 랜딩 페이지의 기술 기반과 구현 경계
- 파트너 신청으로 연결되는 공개 전환 퍼널의 정보 구조
- 정적 콘텐츠를 중심으로 한 Astro 페이지 구조
- 필요한 상호작용만 React island로 분리하는 프런트엔드 경계
- 검색 엔진과 공유 미리보기를 고려한 문서·메타데이터 기반
- 모바일과 데스크톱을 함께 고려하는 반응형 웹 기반

이 범위는 `1qpartners-LANDING` 저장소에서 확인된 내용이다. 실제 담당 범위와 성과는 프로젝트 진행에 따라 [[career-notes|경력 정리 노트]]에 갱신한다.

## 경력 정리 관점

이 프로젝트는 단순 랜딩 페이지 제작보다, 여러 이해관계자의 복잡한 오프라인 견적 업무를 디지털 서비스 경계로 정리하는 경험에 의미가 있다. 경력 문서에는 다음 관점으로 증거를 축적한다.

- 다중 사용자 서비스에서 공개 랜딩과 인증 후 포털의 책임을 나눈 과정
- 확정되지 않은 신청 정책과 API를 프런트엔드 구현에서 분리한 판단
- 정적 콘텐츠와 상호작용 영역을 구분해 Astro와 React의 역할을 정한 과정
- 파트너 모집에서 신청 전환까지의 사용자 흐름과 정보 구조를 설계한 경험
- 구현 중 발생한 기술 문제와 해결·검증 과정을 [[incidents/index|트러블슈팅 기록]]으로 보존
