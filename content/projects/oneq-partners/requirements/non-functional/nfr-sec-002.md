#### 품질 요구사항

시스템은 화면 표시 여부와 관계없이 모든 보호 요청에서 서버가 요청 주체의 역할과 대상 데이터의 소유·귀속 관계를 검증하고, 허용되지 않은 사용자·업체·역할의 조회와 변경을 차단해야 합니다.

#### 목적·영향

클라이언트 화면의 숨김 처리만으로는 직접 API 요청을 막을 수 없으므로, 역할별 업무 범위와 데이터 귀속을 서버에서 강제하여 타 사용자·타 업체 데이터 노출과 변경을 예방합니다.

#### 적용 조건

- 환경: 운영·검증 환경
- 적용 시점: 인증이 필요한 화면·API의 조회·등록·수정·삭제·상태 변경 시
- 제외 조건: 로그인·인증 시작 등 공개가 명시된 엔드포인트

#### 기준 미충족·예외 처리

- 미충족 시 처리: 타 사용자·타 업체 데이터가 한 필드라도 노출되거나 변경되면 출시 차단 결함으로 처리
- 예외 허용 조건: 공개 범위가 FR 또는 권한 정책에 명시되고 개인정보·영업정보가 포함되지 않은 경우
- 예외 승인 주체·기한: 기획 책임자와 개발 책임자 공동 승인 / 운영 배포 전

#### 검증·수용 기준

- Given: 파트너·고객·공급업체·운영사 계정과 서로 다른 소유자의 데이터가 준비되어 있음
- When: 각 역할이 본인 데이터와 타인 데이터를 화면 및 직접 API로 조회·변경함
- Then: 허용 범위만 처리되고 거부 요청은 데이터 노출 없이 차단되며 거부 로그가 남음
- 검증 근거: 역할별 정상·음수 테스트 결과, 권한 거부 로그
