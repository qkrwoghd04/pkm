## 요구사항

고객은 본인 상담 신청을 조회하고 허용된 처리 단계까지 신청 내용을 수정하거나 취소할 수 있어야 하며, 운영사는 변경 결과를 확인할 수 있어야 한다.

## 배경·목적

현재 시나리오는 신청 제출만 제공하며 제출 이후 오류 수정·철회·중복 신청 처리 방법이 없다.

## 대상·범위

- 포함: 신청 상세 조회, 수정·취소, 취소 사유, 변경 이력
- 제외: 계약(CT) 도메인과 계약 이후 실제 이행
- 적용 채널·환경: 고객 모바일 웹·앱, 원큐 운영사 PC 어드민 웹

## 조건·업무 흐름

- 사전 조건: 고객 본인에게 연결된 상담 신청이 존재한다.
- 트리거: 고객이 신청 상세에서 수정 또는 취소를 요청한다.

1. 시스템은 신청 상태와 본인 여부를 확인한다.
2. 허용 단계이면 변경 내용을 저장하거나 신청을 취소한다.
3. 변경 결과와 이력을 운영사에 제공한다.

## 대안·예외 흐름

| 발생 조건              | 업무 처리                             | 최종 결과      |
| ---------------------- | ------------------------------------- | -------------- |
| 견적 요청 발송 후 수정 | 직접 수정을 제한하고 상담사 문의 안내 | 변경 요청 대기 |
| 중복 신청              | 고객과 운영사에 중복 가능성을 표시    | 검토 대기      |
| 본인 인증 실패         | 신청 정보 접근을 차단                 | 인증 필요      |
