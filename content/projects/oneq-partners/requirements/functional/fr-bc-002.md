## 요구사항

원큐 운영사 관리자는 고객에게 제공할 업종의 명칭·노출 순서·사용 상태를 관리할 수 있어야 한다.

## 배경·목적

고객에게 노출되는 업종 목록을 운영사가 직접 관리하여 제공하지 않는 업종이 신청에 사용되거나 노출 순서가 임의로 달라지는 것을 방지한다.

## 대상·범위

- 포함: 업종 등록·수정, 노출 순서, 활성·중지, 초기 데이터 검증
- 제외: 계약(CT) 도메인과 계약 이후 실제 이행
- 적용 채널·환경: 원큐 운영사 PC 어드민 웹, 고객 모바일 웹·앱

## 조건·업무 흐름

- 사전 조건: 관리자가 업종 기준정보 관리 권한을 보유한다.
- 트리거: 관리자가 업종을 추가하거나 노출 설정을 변경한다.

1. 관리자는 업종명과 노출 정보를 등록·수정한다.
2. 시스템은 활성 업종만 고객에게 제공한다.
3. 사용 중지된 업종의 기존 신청 이력은 유지한다.

## 대안·예외 흐름

| 발생 조건                       | 업무 처리                          | 최종 결과 |
| ------------------------------- | ---------------------------------- | --------- |
| 기존 신청이 있는 업종 삭제 요청 | 삭제 대신 사용 중지를 안내         | 사용 중지 |
| 중복 업종 등록                  | 중복 가능성을 표시하고 저장을 제한 | 등록 보류 |
| 노출 순서 충돌                  | 유효한 순서를 재입력하도록 안내    | 변경 보류 |

## 기준 문서

- 정책·업무 규칙: 도메인별 정책
- 상태: 상태 정의
- 권한: 권한 정책
- 데이터:
  - 식별·관계: 업종 ID, 업종 코드
  - 업무 입력·결과: 업종 명칭, 노출 순서, 기존 고객 신청 사용 여부
  - 상태·이력: 활성·중지 상태, 등록자·등록 시각, 수정자·수정 시각

## 수용 기준

- Given: 운영사가 관리할 업종이 등록되어 있다.
- When: 관리자가 업종 명칭·노출 순서·사용 상태를 변경한다.
- Then: 변경 결과가 저장되고 활성 업종과 순서만 고객의 업종 목록에 반영된다.

- When: 업종을 등록·수정·중지
- Then: 고객에게 최신 활성 업종과 순서가 반영되고 기존 이력은 유지된다.
