## 요구사항

고객은 서비스 신청에 사용할 업종을 조회하고 하나를 선택할 수 있어야 한다.

## 배경·목적

고객이 서비스 신청에 사용할 업종을 조회하고 하나를 선택한다.

## 대상·범위

- 포함: 위 요구사항을 달성하는 데 필요한 업무 결과와 사용자 흐름
- 제외: 화면·API·필드 수준의 구현 명세는 관련 기능(F) 문서에서 관리
- 적용 채널·환경: 고객 모바일 웹·앱, 원큐 운영사 PC 어드민 웹

## 조건·업무 흐름

- 사전 조건: 고객이 서비스 신청을 시작한다.
- 트리거: 고객이 업종 선택 단계에 진입한다.

1. 시스템은 신청 가능한 업종 목록을 제공한다.
2. 고객은 하나의 업종을 선택한다.
3. 선택된 업종을 서비스 신청과 연결한다.

- 업무 규칙: 업종 목록과 세부 서비스 구성은 미정이다.
- 업무 규칙: 선택 업종은 견적 요청 대상 공급업체를 찾는 기준으로 사용한다.

## 대안·예외 흐름

| 발생 조건                                        | 업무 처리                                        | 최종 결과 |
| ------------------------------------------------ | ------------------------------------------------ | --------- |
| 선택 가능한 업종이 없으면 신청을 진행할 수 없다. | 선택 가능한 업종이 없으면 신청을 진행할 수 없다. | 처리 제한 |

## 기준 문서

- 정책·업무 규칙: 도메인별 정책
- 상태: 상태 정의
- 권한: 권한 정책
- 데이터:
  - 식별·관계: 업종 ID, 고객 신청 ID
  - 업무 입력·결과: 신청 가능한 업종 명칭·노출 순서, 고객이 선택한 업종 ID
  - 상태·이력: 업종 활성 상태, 업종 선택 시각

## 수용 기준

- Given: 고객이 서비스 신청을 시작한다.
- When: 고객이 업종 선택 단계에 진입한다.
- Then: 고객 신청에 선택 업종이 저장된다. 또한 견적 요청 시 동일 업종의 공급업체 목록을 조회할 수 있다.
