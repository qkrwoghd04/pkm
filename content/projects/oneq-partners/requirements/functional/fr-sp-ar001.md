## 요구사항

원큐 운영사 관리자는 영업 파트너 신청을 검토해 보완 요청·승인·반려하고 처리 결과를 신청자에게 안내할 수 있어야 한다.

## 배경·목적

영업 파트너 신청의 검토·보완·승인·반려 결과를 일관되게 관리하고, 승인된 신청만 추천코드·QR 발급 단계로 전달한다.

## 대상·범위

- 포함: 위 요구사항을 달성하는 데 필요한 업무 결과와 사용자 흐름
- 제외: 화면·API·필드 수준의 구현 명세는 관련 기능(F) 문서에서 관리
- 적용 채널·환경: 원큐 운영사 PC 어드민 웹, 영업 파트너 포털

## 조건·업무 흐름

- 사전 조건: 영업 파트너 신청이 접수되어 있다.
- 트리거: 원큐 운영사 관리자가 신청을 검토한다.

1. 관리자는 신청 정보와 사업자 정보를 확인한다.
2. 보완이 필요하면 보완 요청과 사유를 기록한다.
3. 승인 또는 반려 결과를 저장하고 신청자에게 안내한다.
4. 승인 결과는 추천코드·QR 발급 요구사항으로 전달한다.

- 업무 규칙: 추천코드와 QR은 승인 완료 시에만 발급한다.
- 업무 규칙: 신청 필드와 승인 검증 기준은 미정이다.

## 대안·예외 흐름

| 발생 조건                               | 업무 처리                                     | 최종 결과 |
| --------------------------------------- | --------------------------------------------- | --------- |
| 필수 정보가 부족함                      | 보완 사유를 기록하고 신청자에게 재제출을 요청 | 보완 요청 |
| 기존 승인 파트너와 사업자 정보가 중복됨 | 기존 파트너 여부를 확인하고 중복 승인을 차단  | 중복 검토 |
| 승인 기준을 충족하지 못함               | 반려 사유를 기록하고 신청자에게 안내          | 반려 완료 |

| --- | --- | --- | | 보완 정보가 필요한 경우 승인하지 않고 보완 요청 상태로 전환한다. | 보완 정보가 필요한 경우 승인하지 않고 보완 요청 상태로 전환한다. | 안내 후 종료 |

## 기준 문서

- 정책·업무 규칙: 도메인별 정책
- 상태: 상태 정의
- 권한: 권한 정책
- 데이터:
  - 식별·관계: 영업 파트너 신청 ID, 승인 후 생성된 영업 파트너 ID
  - 업무 입력·결과: 신청자·사업자 정보, 보완·승인·반려 결과와 사유, 신청자 안내 결과
  - 상태·이력: 검토 상태, 검토자, 처리 시각

## 수용 기준

- Given: 검토 가능한 영업 파트너 신청이 접수되어 있다.
- When: 관리자가 신청을 보완 요청·승인 또는 반려한다.
- Then: 처리 결과와 사유가 저장되고 신청자에게 안내되며, 승인된 신청만 추천코드·QR 발급 단계로 전달된다.

- When: 원큐 운영사 관리자가 신청을 검토한다.
- Then: 승인된 파트너가 추천코드와 개인 QR을 조회할 수 있다. 또한 보완 요청된 신청은 파트너가 수정·재제출할 수 있다.
